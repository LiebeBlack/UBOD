Binarios compilados

Ejecutables del Sistema

Binarios compilados nativamente en Rust sin requerir máquina virtual, runtime de scripting ni bibliotecas externas C heredadas.

Binario Función Principal Garantías Operativas
vault-gui Aplicación gráfica de escritorio para gestión diaria, búsqueda, consulta de auditoría y papelera. Interfaz acelerada por GPU (OpenGL/Wayland/X11), 100% ventanas sin necesidad de consola de comandos. Confinamiento de escritura en Linux.
vaultd Demonio de servicio central: motor de la bóveda, panel web local (HTTP loopback), servidor mTLS y anuncio mDNS. Auto-restringido mediante Landlock. Bloqueo atómico de escritor único.
vaultctl Cliente de consola: descubrimiento en red local, emparejamiento con código OTP, consulta de manifiestos y subida de archivos. Ideal para automatizaciones, terminales de cátedra o digitalizadores desatendidos.

Pila de software

Pila Tecnológica y Primitivas Criptográficas

Seguridad & Criptografía

  • TLS 1.3 puro: Implementado con rustls. Sin OpenSSL, sin dependencias dinámicas C ni superficie de ataque heredada.
  • PKI Interna P-256: Autoridad Certificadora (CA) propia en curva P-256; emisión de certificados de cliente tras emparejamiento válido.
  • Cifrado AEAD: XChaCha20-Poly1305 para la base de metadatos, asociando la posición de bloque como dato autenticado (AAD).
  • Hashing & Derivación: SHA-256 + BLAKE3 para el contenido; Argon2id para PIN de acceso.
  • Estampado Temporal: Tokens RFC 3161 con ASN.1 DER y firmas criptográficas verificables.

Plataforma & Ejecución

  • Runtime Asíncrono: tokio para alta concurrencia y gestión eficiente de I/O en el canal mTLS.
  • Interfaz Gráfica: egui / eframe con renderizado por hardware OpenGL/Wayland/X11 y selector de archivos embebido.
  • Procesamiento Documental: lopdf para PDF nativo y descompresor ZIP para contenedores OOXML/ODF.
  • Sandboxing: Confinamiento de sistema mediante Landlock en núcleos Linux modernos.
  • Configuración: Formato TOML seguro con validación estricta de esquemas mediante serde.

Protocolo de red

Protocolo del Canal mTLS de Dispositivos

Los terminales de cátedra y estaciones de digitalización se comunican mediante endpoints HTTPS/mTLS autenticados:

Endpoint Método Autenticación Carga Útil / Respuesta
/v1/pair POST Código OTP de 1 solo uso (10 min) Envía {code, device_id} → Devuelve certificado y clave de cliente con huella SHA-256 firmada.
/v1/ping GET mTLS con certificado autorizado Verificación de estado de bóveda, capacidad y versión de protocolo activa.
/v1/manifest GET mTLS con certificado autorizado Lista de hashes SHA-256 presentes en la bóveda (prevención de reenvíos innecesarios).
/v1/upload POST mTLS con certificado autorizado Envelope JSON de metadatos en la primera línea + flujo binario del documento.

Estructura del Envelope JSON

Cada entrega declara metadatos que la bóveda recalcula y verifica antes de admitir: 

{
  "header": {
    "device_id": "term-catedra-02",
    "timestamp_utc": 1758816400,
    "protocol_version": "1.0"
  },
  "payload": {
    "file_name": "Tesis_Postgrado_2026.pdf",
    "file_category": "Tesis",
    "file_size_bytes": 14205840,
    "sha256": "e3b0c44298fc1c149afbf4c8...",
    "title": "Criptografía Aplicada a Datos",
    "department": "Ciencias de la Computación",
    "academic_year": 2026
  }
}

Garantías del Canal Seguro

  • Emparejamiento Efímero: Código OTP con caducidad improrrogable de 10 minutos.
  • Filtro por Huella Criptográfica: Cada solicitud valida la huella digital del certificado contra la base local de dispositivos aprobados.
  • Aislamiento de Carga: Todo envío se deposita en staging; no alcanza la bóveda final hasta su admisión formal.
  • Límites Estrictos de Conexión: Timeouts contra conexiones lentas o colgadas y descarte inmediato ante excesos de tamaño.

Almacenamiento físico

Estructura de Datos en Disco

Directorio por defecto en despliegue estándar: /opt/intranet-suite/data/ (o ~/.boveda/ para despliegue de usuario):

Ruta de Archivo / Directorio Contenido & Tratamiento de Seguridad
vault.key Clave maestra criptográfica de 64 bytes generada con CSPRNG del kernel. Permisos 0600. Sin ella la base es irrecuperable.
db/vault.db.enc Base de metadatos, índices catalográficos e historial de versiones, protegida con cifrado XChaCha20-Poly1305.
pki/, tsa/, ca.pem Autoridad de Certificación local y sellador temporal cualificado. El certificado público de CA se entrega en el emparejamiento.
config/vault.pub Clave pública institucional de verificación y cifrado de reportes de diagnóstico.
config/rules.toml Reglas de clasificación automática según taxonomía institucional y patrones de archivo.
vault/ Documentos custodiados admitidos: sellados con doble hash, marcados inmutables (chattr +i) e indexados para búsqueda.
staging/ Directorio de cuarentena transitoria donde se verifican las cargas entrantes antes de su sellado definitivo.

Referencia operativa

Comandos y Sintaxis de Uso

Servicio Central (vaultd)

# Inicialización guiada y arranque inmediato
vaultd --quickstart MiClaveSegura2026

# Configuración única de PIN de acceso
vaultd --init MiClaveSegura2026

# Arranque ordinario del demonio y panel web
vaultd

# Modo depuración sin confinamiento Landlock
vaultd --no-landlock

Cliente de Terminal (vaultctl)

# Descubrir servicios de bóveda en red local
vaultctl discover

# Emparejar terminal con código OTP de 10 min
vaultctl pair 127.0.0.1:8642 984120 term-01 --ca ca.pem

# Subir documento con envelope de metadatos
vaultctl upload 127.0.0.1:8642 acta_2026.pdf --categoria Acta

# Comprobar estado de conectividad mTLS
vaultctl ping 127.0.0.1:8642

Aplicación de Escritorio (vault-gui)

# Lanzar interfaz gráfica nativa en Rust
vault-gui

# Lanzar sin restricción de sandbox de escritura
vault-gui --no-landlock

Instalación Institucional Portable

# Despliegue en /opt y creación de lanzador de escritorio
sudo ./scripts/install-portable.sh --desktop

# Desinstalación limpia sin dejar residuos
sudo ./scripts/uninstall-portable.sh

Especificación de límites

Alcance Técnico y Límites de Diseño

Alcance Garantizado

  • Host Linux Dedicado: Diseñado para operar con máxima seguridad en un equipo institucional independiente.
  • Loopback por Defecto: Panel de control (puerto 8443) y canal mTLS (puerto 8642) escuchan en 127.0.0.1 por defecto.
  • Descubrimiento Local Controlado: Soporte de mDNS para red de cátedra, configurable y deshabilitado por omisión.
  • Trazabilidad Universal: Cada alteración, admisión o versionado deja constancia en la cadena de auditoría criptográfica.

Límites Operativos

  • Escritor Único: Un solo proceso puede escribir en la base simultáneamente para evitar desincronizaciones de base de datos.
  • Requisitos del Filesystem: El atributo inmutable (chattr +i) requiere soporte en el sistema de archivos (ext4, XFS, Btrfs).
  • Herramientas Externas para OCR: La extracción en imágenes escaneadas requiere tesseract-ocr instalado.
  • Continuidad Institucional: La recuperación ante desastres recae en la custodia física y respaldo periódico del archivo vault.key.
